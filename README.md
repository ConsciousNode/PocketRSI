## 1. Safety & Sandbox Architecture ("The Jar Is Real")

Both `pocketrsi.html` and `examiner.html` enforce strict air-gapped isolation:

- **Strict Content-Security-Policy (`<meta>` in `<head>`)**:
  ```html
  <meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' blob:; style-src 'unsafe-inline'; img-src data: blob:; worker-src blob:; connect-src 'none'; font-src 'none'; frame-src 'none';">
  ```
- **Zero Network Calls**: No `fetch`, `XMLHttpRequest`, `WebSocket`, `RTCPeerConnection` (WebRTC), `EventSource`, `navigator.sendBeacon`, or external URLs of any kind.
- **Zero Persistent Storage**: No `localStorage`, `sessionStorage`, `indexedDB`, `document.cookie`, or Cache API.
- **Germline-Only Egress**: The only way state ever leaves the tab is when the user explicitly clicks **Save Descendant (.html)** or **Export Scorecard (.json)**.
- **Grader Separation**: Official evaluation scores come exclusively from `examiner.html`, which statically parses descendant HTML files without executing their page scripts and evaluates them inside its own interpreter against a disjoint `0b11` secret seed partition.

## 3. How to Run a Lineage & Verify Everything

### 3.1 Running the Jar (`pocketrsi.html`)
1. Open `pocketrsi.html` directly in any modern browser (`file://` or local preview).
2. Choose a rung in **Section III (Rung Selection)**:
   - **Auto-Cycle Ladder (1:Weights → 2:Recipe → 3:Code GP)** (default), or lock to a single rung.
3. Click **Evolve +1 Gen**, **Evolve +5 Gens**, **Evolve +20 Gens**, or toggle **Auto-Run: ON** to watch the homunculus in the jar train continuously while the tab stays open.
4. Click any node in the **Lineage Tree** (`Section I`) to inspect its hashes and unified genome diff:
   - Click **Rewind to Gen k** to deterministically rebuild that exact ancestor from Gen 0 + diffs.
   - Click **Fork Here** to start a new unmerged branch (`fork-gN`) from that ancestor.
5. Toggle **Ouroboros Mode** to unlock `@scorer` in the GP-DSL and watch the jar wirehead its own dev evaluator in real time.
6. Click **Save Descendant (.html)** to export a standalone descendant HTML file with the current genome, weights, and full hash-chained lineage baked in.

### 3.2 Auditing with the Examiner (`examiner.html`)
1. Open `examiner.html` in a browser. On startup, it immediately audits the pre-loaded 20-generation honest lineage (`runs/pocketrsi_gen_020.html`) and runs the 9-vector tamper rejection suite.
2. Drag and drop any exported `pocketrsi_gen_NNN.html` or `ouroboros_gen_NNN.html` file into the drop zone (or click **Audit 10-Gen Ouroboros Run** to inspect the wireheading positive control).
3. Click **Export Scorecard (.json)** or **Export Lineage Plot (.png)** to save the cryptographically signed grader report containing `examiner_sha256`.

### 3.3 Running the Headless Test Suite (`node tests/run.js`)
Run from the project root with Node.js (v18+, zero `npm` dependencies required):
```bash
node tests/run.js
# Or swap in your own test seed offset:
node tests/run.js --seed=123456
```

## 4. How to Read the Charts

### In `pocketrsi.html` (Center Column):
- **Plate 1 — Three-Plate Score Trajectory**:
  - **Solid Green Line (`●` Solid Dots / `○` Hollow Circles)**: Current instance dev score on the 5-family dev seed partition (`0b10`). Solid dots mark generations accepted by the dev gate; hollow red circles mark candidate generations rejected by the gate (where active weights remained at the parent).
  - **Dashed Blue Line (`--`)**: Parent instance score evaluated on the same seeds.
  - **Dotted Gray Line (`··`)**: Frozen Gen-0 twin baseline (embedded in `#rsi-gen0-weights` and never modified).
  - **Solid Red Line (Ouroboros Mode)**: Self-reported wireheaded dev score vs the dotted green unhacked anchor score, visualizing the Goodhart delusion gap.
- **Plate 2 — Meta-Curve (Rate of Improvement)**:
  - **Blue/Red Bars**: Raw score delta ($\Delta \text{Score}$) per generation.
  - **Solid Amber Curve**: 3-generation smoothed rate of improvement ($\Delta \text{Score} / \text{Gen}$), showing how Rung 2 (Recipe) and Rung 3 (Code GP) accelerate sample efficiency before reaching the 7,056-parameter capacity ceiling around Generation 17.
- **Plate 3 — Live Procedural Task Probe Matrix**:
  - Displays token-by-token input contexts (gray chips), exact model predictions matching ground truth (green `tok→pred` chips), and errors (red `tok→pred(expected)` chips) across all five procedural task families (`ARITH-CARRY`, `DYCK-STACK`, `GRAMMAR-XFER`, `CA-PARITY`, `COPY-KV`).

### In `examiner.html` & `runs/lineage_plot.png`:
- **Solid Green Curve**: Official Examiner Combined Secret Score ($0.70 \times \text{Secret In-Distribution} + 0.30 \times \text{Secret OOD Generalization}$) evaluated on the Examiner's `0b11` secret vault seeds.
- **Dotted Blue Curve**: Examiner Out-of-Distribution (OOD) generalization score on longer sequence lengths and deeper compositional clauses.
- **Dashed Red Curve**: The jar's self-reported dev score from its lineage ledger.
- **Red Circle Markers (`GOODHART: Dev↑ Exam↓`)**: Generations flagged by the Examiner where the jar's self-reported dev score rose while its true Examiner held-out score fell or stagnated under wireheading.
